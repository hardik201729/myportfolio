The short version

The analyst team had become a human cache for the same 40 questions. Instead of hiring, we put those questions behind an LLM that writes SQL against a curated metric layer, checks itself against golden answers and masks PII. Now 80–90% of questions answer themselves.

01

Context

Leadership at PrepLadder made daily decisions on numbers: signups by city, paid conversion by plan, which live class was losing viewers. Every one of those numbers went through a 3-person analytics team.

Questions waited one to two days. Analysts spent their weeks on repeat requests instead of the deeper analysis they were hired for. The ask was to hire another analyst.

02

The problem behind the problem

I logged every data request for 3 weeks: who asked, what they asked and how the analyst answered it. 640 requests later, the shape was obvious.

We didn't have an analyst shortage. We had a repetition problem.
03

What we built

The key decision was what the model could see. Letting an LLM write SQL against raw production tables is how you get confident wrong numbers. We gave it a curated metric layer instead: 60 defined metrics, each with an owner and a tested SQL definition.

Guardrails

  • PII never leaves the warehouse. Phone numbers, emails and payment details were masked at the view level, so the model never saw them.
  • Role-based access. A marketing manager could ask about campaigns, not payroll.
  • Show your work. Every answer came with its SQL and the metric definition. Trust came from transparency, not from a confidence score.

05

What I learned

  • Log before you build. Three weeks of request logs were worth more than any brainstorm.
  • Constrain the model. The curated metric layer did more for accuracy than prompt engineering.
  • Adoption follows trust, and trust follows transparency. Showing the SQL made sceptics into daily users.
